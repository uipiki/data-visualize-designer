# データ視覚化のデザイン原則

Data Visualize Designerに組み込まれているデザイン原則をまとめたドキュメント。

## 原則1: 伝えたいメッセージを明確にする

データの視覚化の大原則として、まずそのグラフで何を伝えたいのかを明確にする必要がある。

**例**: 「私の戦闘力は53万」
- BAD: 数字だけのリスト
- GOOD: 横棒グラフで比較対象と並べて表示

**実装**: タイトル入力欄を設置し、グラフ上部に表示

---

## 原則2: データの大きさを表すには比較する

分析というのは比較してはじめて意味を持つ。データの背景として比較対象があってはじめて伝わる。

**実装**: 複数データ行の入力UIを提供

---

## 原則3: 棒グラフは原点をゼロにする

棒グラフは棒同士の面積を直感的に見比べるためのグラフ。原点を変えると本来のデータが持つ大きさを視覚的に比較できなくなる。

- 印象操作と思われると信用を失う
- ツールが自動調整するケースに注意

**実装**: X軸の`domain`を`[0, 'auto']`に固定

---

## 原則4: 要素を最低限に減らす

グラフを構成する要素は、伝えたいメッセージを表現する上で必要最低限に抑える。

- 「要素がひとつ増えるごとに認知的負担は増える」
- Y軸の目盛りや補助線も必要でなければ削除
- 常に引き算で考える

**実装**: グリッド線なし、Y軸目盛りなし、データラベルのみ表示

---

## 原則5: 縦軸は自然な数字を使う

ツールの自動設定に任せると読みにくい目盛間隔になることがある。

**不自然な例**:
- 0, 3, 6, 9, 12, 15...
- 0, 4, 8, 12, 16, 20...
- 0, 0.4, 0.8, 1.2, 1.6...

**自然な例**:
- 0, 2, 4, 6, 8, 10...
- 0, 5, 10, 15, 20, 25...
- 0, 0.5, 1.0, 1.5, 2.0...

**実装**: 1, 2, 5, 10, 20, 50, 100...刻みに自動調整するロジック (`calculateTicks.ts`)

---

## 原則6: 何かを連想するような色を使わない

グラフで伝えたいメッセージと関係のないものを連想するような色を避ける。

**例**: 正月のグラフに赤緑（クリスマス連想）はNG

- 特に強調するものがなければ色の濃淡で区別
- 色覚異常への配慮: 明度が近い色（赤緑）はモノトーンで区別不能
- 濃淡なら誰でも判別可能

**実装**: 同系色の濃淡パレットをデフォルトに使用（Blue, Green, Purple, Gray, Orange）

---

## カラーテーマ一覧

| テーマ名 | 色範囲 | 用途 |
|---------|--------|------|
| Blue | #1E40AF → #EFF6FF | 汎用・ビジネス |
| Green | #166534 → #F0FDF4 | 成長・環境 |
| Purple | #5B21B6 → #F5F3FF | クリエイティブ |
| Gray | #374151 → #F9FAFB | ニュートラル |
| Orange | #C2410C → #FFF7ED | エネルギー |

各テーマは同系色の濃淡で構成されており、色覚異常の方でも明度差で判別可能。
